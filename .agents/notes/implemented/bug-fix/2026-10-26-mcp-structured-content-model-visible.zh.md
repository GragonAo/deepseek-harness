# Agent Note: MCP 结构化结果以文本形式抵达模型

Status: implemented

[English](2026-10-26-mcp-structured-content-model-visible.md) | 中文

## Problem

带 `structuredContent` 的工具结果，抵达模型时只有它 `content` 块里那句占位文本——本篇针对的服务器返回的就是字面一行 `result in structuredContent`——载荷本身不在请求里。MCP 把结果分成两半：`content` 块给渲染文本的客户端，`structuredContent` 给想程序化取值的客户端。桥接在规范值里两半都留下了，但它的 Native 投影只从 `content` 拼模型看到的文本，于是「数据 + 占位」的服务器恰好在模型唯一读取的位置丢掉了数据。

这种失败是静默的。调用成功，模型收到一个格式完好结果，唯一症状是回答里说数据在模型看不到的地方。

## Decision

`createOutput().render` 投影内容块，并在结果带有 `structuredContent` 时，把该值的紧凑 JSON 序列化追加到新的一行。三个细节承载了这个决定：

- **投影文本中已经含有该序列化时不追加。** MCP 规范要求填充 `structuredContent` 的服务器同时把 JSON 内联成一个文本块，供只读文本的客户端使用；这类服务器发出的文本原样保留，载荷只出现一次。
- **`content` 为空数组时只渲染该序列化**，而不是先给一句「无可见内容」的占位再接上数据。
- **规范值不变。** 程序化调用方和 Code Mode 仍分别收到 `content` 与 `structuredContent`；只有 Native 文本投影多出这份序列化。

## Alternatives considered

- **要求服务器把序列化内联进 `content`** — 拒绝：部署方无法改写拿到的服务器，占位加结构化载荷是合法的 MCP 响应，而只对合规服务器有效的 harness，会把同一缺陷复制给每一个服务器写法相反的部署。
- **用 `structuredContent` 取代内容文本渲染** — 拒绝：这会丢掉投影为被拒绝的图片、音频、嵌入资源、资源链接和不受支持的块添加的诊断，也会丢弃服务器确实随数据一起发出的人类可读文本。
- **为「是否暴露结构化内容」增加按服务器的配置开关** — 拒绝：一个工具自身结果的可见性，不是调用方在不审计每个服务器响应格式与每个模型任务的情况下能正确作出的部署选择；这个部署里没有任何需求要文本专用的行为。
- **为追加的序列化设置上限或截断** — 拒绝：没有证据支持某个阈值，静默截断会把解析结果与服务器实际返回值不同的 JSON 交给模型。无上限的代价改为记录在「已知限制」中。

## Consequences

通过结构化通道作答的服务器，其载荷现在会进入模型上下文，「只有占位、模型完全拿不到数据」的情形消失了。随之而来两项代价。只要服务器填充 `structuredContent`，结果抵达模型时文本就更多，包括已经把 JSON 内联的服务器；`includes` 判断避免了重复，但无法缩小那一份。追加本身也没有上限，因此返回大结构化值的服务器会让这些 token 在会话之后的每次请求中都被支付——上限只能来自服务器，因为投影没有截断设置。

投影仍是规范值的纯函数，所以值、会话事件和模型看到的文本仍出自同一来源，也没有任何模型新可见的内容是尚未记录的。

## Testing

`tests/mcp-client.spec.ts` 经注册表执行器覆盖三个分支：占位文本加 `structuredContent` 会追加序列化；`content` 为空数组时只渲染序列化；已内联的序列化不重复。断言纯文本结果、空结果和诊断占位的既有测试均未改动——这正是投影对不带 `structuredContent` 的结果仍保持原样的证据。
