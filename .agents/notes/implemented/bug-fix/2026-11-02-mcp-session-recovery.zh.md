# Agent Note: 服务端已遗忘的 MCP 会话要重新握手

Status: implemented

[English](2026-11-02-mcp-session-recovery.md) | 中文

## Problem

Streamable HTTP 的 MCP 服务端把会话放在进程内存里，一旦该会话不存在（重新发布、进程重启或过期），它就对自己签发过的 `Mcp-Session-Id` 回 `404`。规范把这个应答定义为"这个 id 没有会话，请重新 initialize"。此时传输层本身是健康的：没有任何东西关闭，`onclose` 不触发，`client.request()` 只是以一个 `code` 为状态码的 `StreamableHTTPError` 拒绝。

连接监管器只对"传输丢失"作出反应，所以这个状态对它不可见。该插件的每一次 `tools/call` 都仍然带着服务端已遗忘的会话发出去，服务端在派发之前逐个拒绝，工具就一直是坏的——直到进程结束；对于一个把全部工具都代理到这类服务端的 harness，这等于整条数据通道停摆。受影响会话里的模型从错误文本正确判断出了这个状态，却让用户去"重启当前对话"，而那没有用：MCP 客户端是按配置的每个服务端一个插件实例，归宿主进程所有，不属于任何会话。

## Decision

`src/session.ts` 用 `isSessionLostSignal(error)` 判定单次失败：只有 `code` 为 `404` 的 `StreamableHTTPError` 才算。只认传输层自己的应答——服务端针对工具本身给出的 JSON-RPC 错误与会话无关；在一个从未建立过会话的传输上收到 404 是端点写错，不是会话过期。

`startConnection` 对外提供 `recoverSession(stale)`：关掉那一代旧连接，把它变成监管器本来就处理的普通断线（带退避重连、重新 initialize、重新同步工具），并解析为下一个成功连上的那一代。等待以 `reconnect.maxDelayMs` 为上限，并在策略放弃、重连被禁用或插件被销毁时提前结束。并发的多次恢复共享一次重连；对已被替换的那一代发起的恢复，直接拿到当前那一代，而不是再起第三代。

`callToolWithinCap` 每次调用最多花掉一次恢复：遇到会话失效的拒绝，就在恢复出来的那一代上重发同一次调用。这次重发对任何工具都安全（包括写工具），因为服务端是在派发之前拒绝了会话——被拒的那次调用没有到达任何工具。第二次同样被拒则交给重连策略处理，而不是让一个等待中的调用自己循环。

## Alternatives considered

**当成普通的工具失败，让模型重试。** 否决：重试不可能成功。过期的 id 由插件实例持有，不属于某一轮，因此之后每次调用、每一轮对话都会以同样的方式失败，直到宿主重启。受影响的那个会话正是这么做的——九次调用加一次 `sleep`——把整轮预算花在了一个无法自愈的错误上。

**让服务端无状态，取消会话。** 在这个包里否决：ICAC 那个部署可以这么做，但这里的 MCP 服务端是第三方，桥接层必须处理规范定义的会话，而不能只处理某个"愿意配合"的服务端选择不再使用的会话。

**会话被拒就重启宿主。** 否决：为了修一条连接而重启进程会中断其他所有租户正在跑的工作，而且这也不是插件能对自己宿主做的事。

**靠匹配服务端文案（"Session not found"）来判定。** 否决：文案是服务端特有的字符串，而规范为这种应答保留的状态码本来就会到达客户端。不按规范回 `400` 的服务端仍然需要人工重启，也就是现状。

**在传输层内部重新 initialize。** 否决：会话 id 和 `initialize` 归 SDK 的传输层所有，工具注册是按代进行的；传输层若在监管器背后自行重新握手，已注册的工具集就会描述一代监管器从未见过的连接。

## Consequences

- 一次会话被拒现在只需一次重连（配置的退避延迟）加一次重发，模型看到的是工具的真正结果，而不是一个它改不动的错误。
- 重发后的调用是模型唯一看到的那一次，因此对话记录与会话日志里是一条 `tool/result`，而不是"失败 + 成功"两条。
- 如果一个端点本身就是配错的 `404` 端点，现在会先尝试一次恢复再失败，随后重连循环报告它一贯报告的那条配置错误。
- 恢复沿用重连策略：`reconnect.enabled: false` 时会话被拒仍然失败，只是要等满 `maxDelayMs`。
- 恢复的等待以 `maxDelayMs` 为界，而不是 `toolCallTimeoutMs`；因此一次工具调用最多可能阻塞这么久才报出服务端的拒绝。
