# Agent Note：交付物声明作为一轮产物的唯一来源

Status: implemented

[English](2026-10-28-deliverable-declarations.md) | 中文

## 问题

业务前端要在每一轮结束时，在这一轮下面列出它交给用户的文件——而且只列这些。会话日志里没有回答这个问题的东西。一轮写过哪些文件，只能从工具流量里推：写文件工具的入参、终端卡声明的产出、diff 卡的位置。每个重建"这一轮交付了什么"的消费者都得从渲染意图再推一遍，而这个推法两头都错：草稿、抽出来的中间数据也算写，于是被算成产物；由命令产出、输出里没点名的文件则被漏掉。UI 想画哪一轮，就得把日志往回翻到那一轮的 `turn/start`，一个气泡一次分页请求。更糟的是没有两个消费者得出同一张表：同一份日志，认得哪些卡片就得出哪张清单。

这里的消费者是办案前端，它要在每一轮下面显示一行产物。它要的不是"这一轮碰过哪些文件"，而是"这一轮交付了哪些文件"——这个区分该由模型来说，不该由启发式去猜。

## 决策

### 由模型声明，不做任何推断

新增 `@deepseek-ai/dsh-tool-present` 包，只注册一个工具 `present`：唯一的参数是这一轮交付的文件列表，以及每个文件配一句说明。这个工具的合同是声明而不是观察：它追加一条 `deliverables/presented` 会话事件，带轮次、发起调用的 `callId` 和解析后的文件列表；它不写文件、不读文件内容，除了"声明已记下"的那句回执之外不产生任何模型可见输出。

模型由同一个包注册的 `systemPrompt` 段落告知何时调用：要交给用户的成品（报告、表格、导出的数据、图）写完之后声明，路径按实际写入的位置给，每个文件配一句它是什么；草稿、临时脚本、抽取的中间数据不声明。这一轮没有交付就不声明。

### 声明折成投影，不在读取时现算

`deliverables/presented` 是只记日志的事件，没有请求侧消费者，所以一条声明永远不会改变模型下一步看到的内容。它的读者是同一个包注册的 `deliverables` 会话投影：整值折叠，一轮一条，按轮次排序，同一轮内按解析后的路径去重，只保留最近 `retainTurns`（默认 50）轮。同一轮里同一路径声明两次时保留先声明的那条，于是后来补的说明不会悄悄改掉前一条。

读的入口是投影，不是日志。会话投影随 `session.history` 的尾页一起下发，所以消费者要读一个会话的任意一轮——最新那轮，或第十轮——都只付一次分页请求，拿到的就是完整的按轮清单。读取路径不再往回翻页、不再扫 `turn/start`、也不再读工具视图。

### 轮次在轮次开着的地方定，不在读的时候推

一条声明属于哪一轮，在追加时沿着会话自己的事件流往回找最近的 `turn/start` 或 `turn/end` 定下来，并写进事件载荷。后一轮因此不会认领前一轮的声明，读的一方也无法重新归属。轮次没开着时调用 `present` 会被拒，而不是记到一个不知道的轮次上。

### 路径先解析，再由消费者翻译

`present` 把每个参数交给会话的 `FileSystem` 服务（`ctx.get('fs')`，可选：没有文件系统的宿主直接拒绝声明，而不是记下未核实的路径），按会话工作目录解析，并记下解析出来的显示路径——多租户部署里就是 `/sessions/<会话 ID>/report.md` 这样的绝对路径。声明时要求路径确实是一个存在的常规文件，一个拼错的名字不会变成用户点不开的链接。

把执行世界里的路径翻译成消费者自己的文件词汇，留给消费者自己做。宿主说的是"交付了什么"，它并不知道某个部署把这些字节寻址成 `session/<会话 ID>/report.md`。翻译不了的路径进 `skipped` 而不是进清单，这正是"沙箱路径可以放心声明"的前提：沙箱一销毁那些路径就没了。

### 工具的渲染意图是普通卡片

`present` 声明的是 generic 卡片并带上原始入参，于是对话记录里它就是一次普通工具调用。这条声明的产物是投影，不是专门的记录视图；专门做一张卡片，只是把投影里已经有的清单再说一遍。

## 备选方案

- **继续从工具流量里推产物。** 否：这个推法只能从"写文件碰巧被渲染成什么样"猜模型的意图，于是把草稿算进去、把命令产出的文件漏掉，还让认得不同卡片的消费者得出不同的表。一个气泡一次分页请求，只是同一个设计带来的症状。
- **用一个约定目录做标记。** 否：那就把一个产品约定变成宿主必须按名字认得的事实——模型写到别处就等于没交付，模型把草稿写进去就等于交付了草稿。声明直接表达意图，文件挪了位置也仍然成立。
- **在助手正文里声明，不用工具调用。** 否：正文没有可折叠的类型化载荷、没有可追溯的 `callId`，也没法拒绝一个不存在的路径。
- **在宿主里现算清单并暴露一个方法。** 否：同一个事实多一个读入口，而且它得在读取时重做轮次归属，又是分页那个问题。投影是宿主处理"由日志事件派生的状态"既有的机制。
- **让 `present` 同时往对话里写一条给用户看的摘要。** 否：模型可见的输出必须能在重放时重建；声明本身已经持久，再往记录里复制一份，会让模型为一个动作回答两次。
- **按字节数或文件数而不是按轮次给投影设上限。** 否：消费者按轮渲染，字节预算会不可预测地整轮丢掉。轮次是这个功能定义的单位，而一轮的声明量本来就被模型写多少限制住。

## 影响

- 一轮的产物清单就是模型声明的那几个：没有推断、没有目录约定、没有按消费者分的规则。不认同的消费者改的是引导语，那是部署配置，不是宿主代码。
- 模型不调 `present` 就没有任何交付。工具引导和部署 persona 承担这条指令；一条从不声明的会话就什么都不渲染。
- 投影只保留最近 `retainTurns` 轮。读比这个边界更早的轮次会得到空清单，而且保留是按轮次而不是按时间界定的。
- 声明是按会话的。两个会话各自交付同一个文件就各自声明，在乎的消费者自己去重。
- `present` 是宿主侧工具，没有客户端半边。渲染这一行的客户端经由自己的传输读投影；部署的业务接口就是这样的一个消费者，代码不在本仓库。
- 事件类型是 `KNOWN_SESSION_EVENT_TYPES` 的成员，于是读到含它日志的构建会解释这份日志，而不是拒绝它。

### 验证

- `packages/deliverables/tool-present/tests/tool-present.spec.ts` 用真实会话与文件系统验工具合同：声明记下轮次、文件与解析后的路径；按会话工作目录解析；轮次没开着、空列表、路径不是存在的常规文件都被拒；同一轮内去重；以及 generic 渲染意图。
- `packages/deliverables/tool-present/tests/projection.spec.ts` 验折叠：轮次顺序、同一路径先声明者胜、`retainTurns` 上限、其它事件返回上一个引用、以及投影能到 `session.history` 的尾页上。
- `pnpm run verify-persistence-catalog` 与 `pnpm run verify-package-invariants` 把事件词汇表和包的 invariant 同伴卡住；两个编译面都会构建这些声明合并。
- 本仓库前面的业务接口验了两层：把投影翻成清单的单元测试（含一份从集群上原样抓下来的尾页），以及一个 standalone MVC 的 HTTP 合同测试——前端真正解析的那段应答。它的真机端到端测试（`DshReportFlowLiveTest`，带 `-Ddsh.live=true` 才跑）在一个真实租户上跑一轮真实对话，断言浏览器会看到的东西：一条带说明与轮次的声明文件、模型自己留的笔记不在清单里、声明的路径读得回来且带 ETag、带 `If-Match` 能保存、旧 ETag 得到 412、只读作用域 403，而会话目录仍能列出两个文件供"在文件夹中显示"。
- 租户部署在 130 测试集群上用真实模型端到端跑过：一轮里写一份报告和一个草稿、只声明报告，`session.history` 的尾页里出现 `deliverables`，带报告在会话目录下的绝对路径与它的说明，没有草稿那一条；宿主重启、从日志重建会话之后投影仍在。
