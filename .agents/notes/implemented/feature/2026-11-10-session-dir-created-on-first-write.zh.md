# Agent Note: 租户文件面在首次写入时建会话目录

Status: implemented

[English](2026-11-10-session-dir-created-on-first-write.md) | 中文

## Problem

会话的工作目录一直只由沙箱的第一条命令建出来（`mkdir -p /sessions/<会话ID>`），没有第二个创建者。当唯一的写入方是会话里的模型时，这是对的：会话还不存在时不会有人往里面写。

对话附件打破了这个前提。用户在发送这一轮之前就在输入框里选好了文件，而产品要把这些字节放进**会话的工作目录**——那个目录就是模型的工作目录：模型在同轮产出的东西旁边读到它们，产物清单能列出它们，业务侧的文件浏览器用同一个地址列它们。但这一刻会话还不存在：产品在发送时写 `session/<会话ID>/uploads/<文件名>`，宿主上没有那个目录。文件面当时答 `404 file-session-unknown`，剩下两条路都不好：让业务侧在外部把目录建出来（等于让业务侧拥有宿主的会话目录布局），或者写进 `user`（那不是模型的工作目录，模型就得为"用户递过来的这一份文件"单独用一个绝对路径）。

## Decision

```yaml
tenant-fs-http:
  createSessionDirs: false
```

`createSessionDirs` 是校验过的 `Config` 字段，默认 `false`。打开后，当 `PUT` 的目标会话目录不存在时，先建出 `<usersRoot>/<主体>/sessions/<会话ID>` 再写。地址规则本身没有任何放宽：会话 ID 仍必须是能成为会话目录名的形状（`sandboxSessionDirOf` 认 `^[A-Za-z0-9][A-Za-z0-9._-]*$`，其余仍是 `400 file-path-invalid`，只是这条检查现在发生在建目录之前而不是之后）；字段关着时应答仍是 `404 file-session-unknown`。

默认关着，是因为建目录不是字节通道答应过的事：调用方只写已存在会话的部署，不该因为路径写错一个字符就能在宿主上留下目录。多租户应用在自己的组装里把它打开（`packages/tenant/tenant-app/src/compose.ts`）——对那个产品来说"在对话里选的附件落进会话工作目录"是产品的一部分，不是部署选项。

沙箱自己那次 `mkdir -p` 是幂等的，所以两个创建方不会打架：谁先跑谁建，另一个看到的是同一层目录。

## Alternatives considered

**业务侧先把会话建出来再上传。** 会话是第一条提示词建出来的，而附件必须在提交那条提示词之前写好——提前建会话要么意味着先发一轮空消息，要么意味着把"建会话"和"第一条消息"拆成两件事。它还会把宿主的会话目录布局变成业务侧的资产，而这正是文件面要拆掉的那种耦合。

**写进 `user` 并要求模型用绝对路径。** 模型的工作目录是会话目录，放在 `user` 下的附件要写成 `/workspace/…`，而同一轮的其他东西都是相对工作目录的路径——一次对话里两套约定；产物清单（`session/<会话ID>/…`）也不会列出用户刚递过来的文件。

**所有作用域都在写入时建目录。** `global` 或 `case` 路径写错一个字符就会静默长出一棵没人要的目录树，而那两个根归别的角色所有。只有 `session` 具备"调用方知道这层目录本来就该存在、只是创建者还没跑"这个性质。

**单独加一个建目录操作。** 多一次调用、多一次要排对的顺序、多一次同样的权限判断，而写入本来就知道自己要这层目录。它能买到的只是"可以建一个空目录"——而一个零字节文件已经更诚实做到了。

## Consequences

文件面在 `session` 作用域上成了目录创建者。约束它的是：可写作用域仍然决定谁能写，只有 `session` 参与，地址里的会话段仍必须是合法的会话 ID 形状。

最后没建起来的会话会在宿主上留下它的 `uploads/` 目录。没有清单会列它，它不在任何已存在的会话里，里面的东西只有那些永远没发出去的附件。清理归会话目录的保留策略；字节通道不为此新增预创建或回收操作。

字段打开后，原来靠 `404 file-session-unknown` 判断"会话还不存在"的调用方就失去这个信号：写入会成功并把目录建出来。本仓的两个调用方只把应答用来报告上传失败，不用它探测会话是否存在；需要旧行为的部署保留默认值即可。

## Testing

`packages/tenant/fs-http/tests/fs-http.spec.ts` 用三种配置起插件：默认配置下，往新会话 `PUT` 得到 `404 file-session-unknown`，且宿主上不会留下目录；`createSessionDirs: true` 下，第一次 `PUT` `session/session-2/uploads/供述材料.pdf` 得到 `200`，字节落在宿主的会话目录里；`createSessionDirs: true` 加一个不可能成为目录名的会话 ID（`会话一`）得到 `400 file-path-invalid`，且什么都没建。
