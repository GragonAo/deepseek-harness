# Agent Note: 由管理平台安装已发布的技能，宿主只负责提交

Status: implemented

[English](2026-11-10-platform-owns-skill-install.md) | 中文

## 问题

[按目录发布已写好的技能](2026-11-10-skill-publish-from-files.md)上线时有两个「这个用户有哪些技能」的写者：`skill_publish` 先把目录装进宿主的用户全局层，再去通知平台，平台再写自己的记录。这个顺序让假状态在两个方向上都可达。

平台那一跳失败的发布，会留下一个平台从不知道的已安装技能：模型能触发它，用户在「我的技战法」里看不见它，页面上也没有任何操作能停用它或删掉它。反过来同样糟——平台记录自己存了一份归档副本，于是之后在页面上重新启用，装进去的可能是与宿主手上那份已经不一致的字节。两个写者、两个真相，而且两边都看不见这个分歧。

平台本来就能把整件事做完。它的 `DshUserSkillInstaller` 拥有「把一个技能写进某个主体的用户全局层」，它的启用链路（`updateStatus(id, 1)`）从存储的归档安装，带 `replace = true`，并且技能没进宿主的技能清单时会失败。宿主侧的安装不是平台缺的能力，而是平台已经拥有的能力的复制品。

## 决定

**只有平台安装。** `skill_publish` 读目录、校验、打包，POST 到 `POST /dsh/inner/skill/ingest`；它从不写技能层。它的结果就是平台的回答。

工具契约上的后果：

- 不再有 `skillInstall` 依赖、没有 `tier` 参数、也没有 `replace` 参数：落哪一层是平台的决定（用户全局，按提交主体分），而提交一个已有的名字会替换先前那条，这与平台导入既有的行为一致。
- `record` 是**必填**配置，不是可有可无的附加项。没有目标的部署拒绝装载，因为它没有任何东西可以安装。
- 拒收现在让整次调用失败。什么都没装，也就没有「成功一半」可报：结果里是平台自己的原话，并明说没有发布成功。
- 提交主体来自 `requireUser()`——请求鉴权后的账号——而不再从已安装目录的路径里反推。

安装能力失去了它为第一版实现新增的第二个入口：`installFromFiles`、`SkillInstallFilesRequest`、`SkillBundleFile`、`readListed` 都已删除。它的测试与上限仍然覆盖它本来就有的归档路径。

文档校验刻意留在宿主：`readSkillDocument` 把宿主安装器稍后会拒的那些问题（没有 frontmatter、`name` 不是小写 kebab-case、`description` 为空）在对话里就指出来，模型当场能改，而不是在上传归档之后变成一次平台拒收。

## 考虑过的其他做法

**保留宿主安装，只把平台记录改成必须成功。** 这能堵住第一个方向（不再有看不见的技能），但第二个方向还在：平台仍持有自己的副本、仍可能装进不同的归档，两次写仍然不是一个事务。而且它制造出「记录失败」这种状态——技能存在，用户却管不了它，正是那条抱怨。

**让工具安装，把平台当作只读投影。** 用户唯一能停用技能的地方是平台页面，所以「技能是否启用」不可能以宿主为准。任何宿主优先的设计最终都要和页面和解。

**让平台安装，但保留 `tier` 以便会话能发布系统级技能。** 系统级技能是部署级的管理动作，在「系统技战法管理」里做；租户会话不该碰到那一层。没有 `tier` 就没有办法要求它，这正是那个论证该有的强制力。

## 后果

宿主与平台现在由构造保证一致：记录行、归档、已安装目录都由平台的导入与启用写下。模型读到的技能清单和用户看到的页面来自同一条记录。

一次失败的发布是干净失败——平台不可达、令牌被拒、名字被拒，都不会留下任何技能。因此发布多了一跳必须成功的往返，而这一跳正是上一版设计想避开、且本来就不该避开的耦合。

`skill-install` 回到只有一个入口（归档），所以 `@deepseek-ai/dsh-tool-skill-publish` 与 `@deepseek-ai/dsh-skill-install` 不再共享「文件直接变目录」这条路径。

## 测试

`packages/skill/tool-skill-publish/tests/publish.spec.ts` 通过 `ctx.tools.execute` 驱动注册好的工具，跑在真实的文件系统与工具能力上，对着一个会记录请求的替身入库端点：它按字节打出的归档（根部 `SKILL.md`、保留嵌套路径、跳过打包噪声）、共享令牌、取自 `runWithUser` 的主体，以及两个表单字段。它钉住遍历的各类拒收（路径不存在、给的是文件而不是目录、根部没有文档、文档装不起来、两个上限）、账号检查，以及平台的每一种结果：拒收信封、只在 `result` 里表达的拒收、非 2xx 状态、不是该信封的 2xx 响应体、被截断的响应体、不可达的端点、到期仍未回话。一个文件系统替身覆盖真实实现无法在每个平台上造出的三种状态（非普通文件条目、列目录之后才涨过上限的文件、读不出来的文件）。装载期拒收覆盖缺少目标、空 URL、两种令牌写法同时给出、两种都没给、`tokenEnv` 指向未设变量，以及每个非正的上限。

`packages/skill/skill-install/tests/skill-install.spec.ts` 只继续覆盖归档路径：安装与它的技能清单刷新、去掉包裹目录、路径规范化、两类拒收、替换，以及一次被中止、层级没有任何改动的调用。
