# `@deepseek-ai/dsh-multi-tenant`

English | [中文](README.zh.md)

The multi-tenant dsh backend as a profile bundle: [`cordis.patch.yml`](cordis.patch.yml) is a patch layer over [`dsh-base`](../base/README.md) + [`dsh-web-app`](../web-app/README.md) that swaps the shared, locally-sandboxed execution world for the tenant container runtime and mounts the tenant carrier. Eleven single-user rows are disabled: `session-persistence-jsonl`, `storage-json`, `settings`, `credentials`, `code-runtime` (the host worker-thread runtime), `subprocess`, `fs-sandbox`, `bash-sandbox`, `sandbox`, `permission`, and `connection` (now that [`agent-http`](../../tenant/agent-http/README.md) owns `/api`). Fourteen rows mount in their place: `container-runtime` (`dsh-container-docker`), `subprocess-container`, `bash-local`, `fs-container` (`root: /workspace`), `code-runtime-container`, `workflow-container`, `session-persistence-postgres`, `storage-postgres`, `settings-postgres`, `credentials-postgres`, `tenant`, `tenant-auth-jwt`, `skill-tier` (`dsh-skill-tier`), and `agent-http`. Five existing rows re-pin a value: `storage-domain` (`backend: postgres`); `sandbox-policy` (`mode: workspace-write`) and `approval` (`policy: ask`), because the tool layer still resolves each call's mode through them; `api-gateway` (`cwd: /workspace`), so sessions without an explicit workspace resolve to the container workspace rather than the Host process cwd; and `tools` (its `mode` defaults to `both`, so a tenant keeps the native tool surface plus the Code Mode `run_code` tool — which runs in the tenant container through `code-runtime-container` — while `DSH_TOOLS_MODE` still overrides). The local `sandbox` executor is replaced by the tenant container as the isolation boundary, and `permission` is disabled because its presets bundle a `danger-full-access` mode and a `shell.sandboxMode` the container executor does not expose — the container always confines to the tenant workspace. The `container-runtime` row reads its `usersRoot` from `DSH_USERS_ROOT`; [`dsh-container-docker`](../../tenant/container-docker/README.md) mounts the per-(tenant, user) execution world — the subject's `/workspace`, the case's shared `/shared`, the subject's `/global` (when `usersRoot` is set), and tooling at `/tools:ro`. The package has no runtime API; the profile composer resolves the patch through the `dsh.bundle.patch` manifest field.

Tenant records, Postgres coordinates (`DSH_POSTGRES_URL`), and auth material (`DSH_OIDC_ISSUER`/`DSH_OIDC_SECRET`) deliberately stay in the deployment's own profile `cordis.patch.yml` (or env): this layer only expresses the provider swap, and an absent value fails loud at load because the tenant providers' config fields are required.

## Model Experience

Indirectly, through the inserted rows: `agent-http` verifies a bearer token and scopes the gateway request to one `(tenant, user)`, and the container providers run every tool call inside that `(tenant, user)`'s container (mounted at `/workspace` with `/shared` and `/global`). The `tools.mode` pin adds the Code Mode `run_code` tool (plus its `tools:sdk` prompt section) to the standard, single-user native tool surface, with its programs executing in the tenant container. This bundle contributes no further model-visible text of its own.

#### KV Cache effect

None directly; each inserted row's package owns its effect.

## Known Limitations and Deferred Work

- **The swap is boot-verified through the Loader, not a real agent turn** — `tenant-demo/tests/multi-tenant-loader.spec.ts` boots base + web-app + this bundle through the Loader (browser-surface rows disabled, tenant rows pinned, deterministic seams hemmed) and asserts each swapped provider resolved; the real-LLM + real-Docker/Postgres closed-loop turn remains the server step.
- **The workspace registry is (tenant, user)-keyed and starts empty in a scope** — it opens each partition's KV domain lazily, so the synchronous `list()`/`get()` projections return empty on first access until an asynchronous method opens that (tenant, user) partition ([`@deepseek-ai/dsh-workspace`](../../workspace/workspace/README.md)).
- **The two carriers are mutually exclusive** — a profile must not also mount `dsh-client-connection`, or `agent-http` and `connection` both register the `/api` prefix and fail the load on a duplicate route.
- **Tenant provisioning stays in the deployment layer** — the `tenant` row boots with zero records; the profile's patch must supply `Config.tenants`.
