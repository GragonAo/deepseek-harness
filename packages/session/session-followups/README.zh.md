# @deepseek-ai/dsh-session-followups

[English](README.md) | 中文

把「答完之后用户可能接着问什么」记成一条会话事实。一个顶层回合正常结束后，本插件让辅助模型给出用户最可能追问的几个问题，并把合格的追问记成仅入日志的 `followup/suggested` 事件。业务面把它折进已经渲染的那一轮，于是追问不占主对话提示词、刷新后仍在，且只凭日志就能重建。

这个生成器是 Cordis 函数插件而非服务：它不拥有任何被其他插件消费的能力，只贡献会话事件。

## 事件契约

两条仅入日志的事件，都在派生的模型历史之外，也都不是 `SurfaceEventType`：

| 事件 | 载荷 | 用途 |
|---|---|---|
| `followup/llm-request` | `turn`、`route`、`system`、`messages`、`maxTokens` | 精确的辅助请求，在派发之前追加。 |
| `followup/suggested` | `turn`、`questions` | 采纳的追问，已去空白、非空、去重，保持模型顺序。 |

`followup/llm-request` 先于它所描述的派发，因此日志里出现追问时，那次调用总能从日志重建（见 [Model-visible ⟺ logged](../../../AGENTS.md#conventions)）。一个回合最多一批：日志里已有该回合的 `followup/suggested` 时生成器直接返回。两条事件都在结束该回合的同一个任务内追加。

## 运行时机

插件监听 `session/event`，在 `turn/end` 的 `reason.kind === 'completed'` 时启动一次独立运行。以下情况跳过：

- 被委派的子会话里的回合（`header.parentSession` 有值，或 `header.origin === 'subagent'`）：没有人读那份记录，追问调用是浪费。
- 最终回答短于 `minAnswerBytes` 的回合：一句确认没有再值得问的追问。
- 该回合已经有一批追问。
- 未配置显式 `provider`/`model` 对、且日志里还没有请求路由的回合。

运行在下一个微任务上启动，因为此刻会话仍在发布 `turn/end` 这次追加，不能被重入追加。于是追问记在回合提交之后，绝不在提交之内。

## 路由与失败契约

`provider` 与 `model` 可选，但必须成对提供。不提供时，生成器使用会话最后一条 `request/header` 的 provider/model 路由，也就是产出该回答的那个模型。超时与插件销毁共用一个中止信号：`timeoutMs` 约束单次调用，销毁插件会中止所有在途运行，等它们落定后其 effect 才返回。

任何失败——没有路由、传输失败、非 `stop` 的结束原因、回复里出现工具调用、回复无法解析——都只让该回合没有追问，并写 `ctx.logger.warn`。不会有异常传回循环：追问是可选的附加物，绝不构成让已完成的回合失败的理由。

最终成帧的用户提示在派发前按 `maxInputBytes` 度量。回答是唯一无界的字段，因此用二分法取能放下的最长前缀，并在截断处加省略号；问题与工具清单永不缩短。只有成帧本身都放不下的预算才会显式报错，而不是发出一个被截断的请求。

## 配置

除成对的路由覆盖外，每个字段都必填；没有默认值。

| 键 | 契约 |
|---|---|
| `instructions` | 非空的、辅助模型要读的任务框定。属于部署政策，因此包内不提供。 |
| `maxQuestions` | 每回合采纳追问数的正整数上限。 |
| `maxInputBytes` | 最终成帧用户提示的 UTF-8 字节正整数上限。 |
| `maxOutputTokens` | 辅助生成的正整数 token 上限。 |
| `timeoutMs` | 运行时限内的正整数端到端期限。 |
| `minAnswerBytes` | 值得追问的最短回答的 UTF-8 字节数，非负整数。 |
| `provider`、`model` | 可选的显式路由；要么都给，要么都不给。 |

## 模型体验

### 辅助追问请求

#### 模型看到什么

追问模型以部署给的 `instructions` 作为系统提示，并收到一条用户消息，内容是 JSON 对象：`question`（开启该回合的人类提问）、`answer`（该回合最终的助手文本）、`tools`（该回合调用过的不同工具名）。模型应以 JSON 字符串数组作答。

#### Token 影响

辅助请求消耗「一回合上下文 + `maxOutputTokens`」的 token；它不属于主 agent 请求，也永不进入派生历史。主对话提示词不含追问的输出格式要求，因此每回合不会为追问花任何指令 token。

#### KV Cache 影响

不使主请求失效。系统框定按部署固定、可跨调用复用；用户消息每回合变化。

## 已知限制与后续工作

- 生成器从会话日志读取该回合的材料，而不是由循环传入，因此在回合提交 `turn/end` 之前就渲染该回合的界面，在事件到达前看不到追问。
- 采纳的追问按原样记录；没有针对部署的「不得提出」的过滤。
- 追问路由默认跟随会话路由；需要隔离辅助流量的部署应显式配置 `provider` 与 `model`。
