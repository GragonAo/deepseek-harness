# `@deepseek-ai/dsh-session-uploads`

[English](README.md) | 中文

业务前端把文件上传到会话目录，随后发出的消息里没有任何文件名，模型无从知道收到了什么。这个插件在每次装配提示词时读一遍部署的上传目录，把目录内容作为动态运行时上下文交给模型，模型据此直接打开文件，而不是反问「上传了什么」。这份贡献是运行时上下文的快照：模型看到的可以从会话日志复原，下一次装配会替换它。

目录按文件系统 Provider 服务的会话目录来定位——`fs-container` 下就是 `/sessions/<会话 id>/uploads`——所以部署配置的是一个名字，而不是宿主路径。既不是文件也不是目录的条目会被丢掉，名字按排序打印，清单有上限。

## Configuration

| 键 | 默认值 | 约定 |
|---|---:|---|
| `directory` | `"uploads"` | 会话目录里存放上传文件的目录。必须是相对路径，且不能含 `..` 段。 |
| `maxEntries` | `40` | 每次装配列出的最大条目数，其余折叠成一个计数。必须是正的安全整数。 |

任何会话目录都无法承载的相对名，或不是正整数的上限，都会在插件加载时失败，而不是拖到第一轮。

## Model Experience

### 收到文件的那次会话的上传清单

#### What the model sees

会话的上传目录非空时，每次装配都会贡献这段运行时上下文。条目按名字排序，大小按二进制单位并从 MB 起保留一位小数，目录带结尾 `/` 且不给大小，超过 `maxEntries` 的条目折叠成一个计数；空目录、不存在的目录、不是目录的路径、以及没有会话的装配，都完全不贡献内容。

##### 上传清单

```markdown
Files the user attached to this session:
- /sessions/6f0c/uploads/供述材料.pdf — 300 KB
- /sessions/6f0c/uploads/现场照片.jpg — 2.0 MB
Read a file with the read tool when its contents matter; read_image reads an image.
```

#### Token effect

与条目数成正比，并由 `maxEntries` 封顶。快照在每次装配时重新生成，从没收到过文件的会话不付任何代价。

#### KV Cache effect

清单落在运行时上下文快照里，harness 把它接在稳定的系统提示词之后。上传文件只改快照，可缓存的前缀不动。

## Known Limitations and Deferred Work

- **名字里带提示词变量语法** — 上下文文本在交给模型之前会做 `{{name}}` 变量插值，所以名字里同时含 `{{` 与其后 `}}` 的文件会让那次装配失败，而不是原样打印。接受这类名字的部署应当在上传时就清洗。
- **没有逐文件的内容预览** — 清单只给名字、大小与类型；文件正文由文件系统工具读取，`read_image` 的图像模态闸门也在那里生效。
- **上传目录是唯一记录** — 清单没有自己的会话事件，两次装配之间到达的文件出现在下一份快照里，没有事件标记它是何时到的。
